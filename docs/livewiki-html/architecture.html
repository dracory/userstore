Architecture

System architecture, design patterns, and key decisions

High-Level Architecture

UserStore follows a layered architecture with clear separation of concerns:

Architecture Layers
  1. Interface Layer - Defines contracts (StoreInterface, UserInterface, RoleInterface)
  2. Implementation Layer - Concrete implementations of interfaces
  3. Data Layer - Database operations and SQL generation
  4. Query Layer - Query builder for complex searches

Core Components

Store Interface

The StoreInterface defines the contract for database operations:

  • Database migration (MigrateUp, MigrateDown)
  • User CRUD operations (Create, Read, Update, Delete)
  • User query operations (FindByID, FindByEmail, List, Count)
  • Soft delete support

User Interface

The UserInterface defines the user entity contract:

  • Property getters and setters (GetID, SetID, etc.)
  • Status checking methods (IsActive, IsInactive, etc.)
  • Role checking methods (IsAdministrator, IsManager, etc.)
  • Password management (SetPasswordAndHash, PasswordCompare)
  • Metadata management (GetMeta, SetMeta, SetMetas)

Role Interface

The RoleInterface defines the role entity contract:

  • Property getters and setters
  • Status checking methods
  • Metadata management

Query Builder

The UserQueryInterface provides a fluent query builder:

  • Filter by various fields (email, name, status, etc.)
  • Pattern matching (LIKE queries)
  • Pagination (Limit, Offset)
  • Sorting (OrderBy, SortDirection)
  • Soft delete inclusion/exclusion

Design Patterns

Interface-Based Design

UserStore uses interfaces to define contracts, enabling:

  • Easy mocking for testing
  • Multiple implementations
  • Loose coupling between components

Method Chaining (Fluent API)

Setters return the interface for method chaining:

user := userstore.NewUser().
    SetStatus(userstore.USER_STATUS_ACTIVE).
    SetFirstName("John").
    SetLastName("Doe").
    SetEmail("test@test.com")

Builder Pattern

The query builder uses the builder pattern for complex queries:

query := userstore.NewUserQuery().
    SetStatus(userstore.USER_STATUS_ACTIVE).
    SetLimit(10).
    SetOrderBy("created_at").
    SetSortDirection("DESC")

Data Object Pattern

User and Role implementations extend dataobject.DataObject for:

  • Automatic change tracking
  • Dirty state management
  • Hydration from database records

Key Design Decisions

Soft Delete Strategy

UserStore uses soft deletes instead of hard deletes:

  • Preserves data for audit trails
  • Enables data recovery
  • Uses soft_deleted_at column with MAX_DATETIME for active records
  • Queries exclude soft-deleted records by default

Metadata Storage

Custom fields are stored as JSON in the metas column:

  • Flexible schema-less storage
  • Easy to add custom fields without migration
  • JSON encoding/decoding handled automatically

Password Security

Passwords are hashed using bcrypt:

  • Automatic hashing via SetPasswordAndHash()
  • Secure comparison via PasswordCompare()
  • Never store plain-text passwords

ID Generation

Uses short ID generation for user-friendly identifiers:

  • Auto-generated on creation
  • URL-safe and human-readable
  • 40-character length

Database Abstraction

Uses SQL builder for database-agnostic queries:

  • Supports SQLite, MySQL, PostgreSQL
  • Driver auto-detection
  • Consistent API across databases

  • github.com/doug-martin/goqu/v9 - Query builder
  • modernc.org/sqlite - SQLite driver
