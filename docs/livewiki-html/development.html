Development

Setting Up Development Environment

git clone https://github.com/dracory/userstore.git
cd userstore

Installing Dependencies

go mod download

go test -cover ./...

go test -v ./...

Code Style Guidelines

Naming Conventions

  • Use Get prefix for getter methods
  • Use Set prefix for setter methods
  • Use Is prefix for boolean check methods
  • Use camelCase for variables and functions
  • Use PascalCase for exported types and functions

Interface Design

  • Define interfaces for all major components
  • Return interface types from functions
  • Use method chaining for setters
  • Keep interfaces focused and cohesive

Error Handling

  • Always return errors from functions that can fail
  • Use descriptive error messages
  • Wrap errors with context when appropriate
  • Check errors immediately after function calls

Testing Guidelines

Writing Tests

  • Write tests for all public functions
  • Use table-driven tests for multiple test cases
  • Mock external dependencies (database, etc.)
  • Test both success and error paths
  • Aim for high code coverage

Test Structure

func TestFunctionName(t *testing.T) {
    tests := []struct {
        name    string
        input   InputType
        want    ExpectedType
        wantErr bool
    }{
        {
            name:    "test case 1",
            input:   testInput,
            want:    expectedOutput,
            wantErr: false,
        },
        // Add more test cases
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := FunctionName(tt.input)
            if (err != nil) != tt.wantErr {
                t.Errorf("FunctionName() error = %v, wantErr %v", err, tt.wantErr)
                return
            }
            if got != tt.want {
                t.Errorf("FunctionName() = %v, want %v", got, tt.want)
            }
        })
    }
}

Continuous Integration

UserStore uses GitHub Actions for CI/CD. The workflow is defined in .github/workflows/tests.yml.

CI Workflow

  • Runs on every push and pull request
  • Executes all tests
  • Checks code coverage
  • Validates Go code formatting

Contributing

Contribution Guidelines

  1. Fork the repository
  2. Create a feature branch (git checkout -b feature/amazing-feature)
  3. Make your changes
  4. Write tests for your changes
  5. Ensure all tests pass (go test ./...)
  6. Commit your changes (git commit -m 'Add amazing feature')
  7. Push to the branch (git push origin feature/amazing-feature)
  8. Open a Pull Request

Pull Request Guidelines

  • Write a clear description of your changes
  • Reference related issues
  • Ensure all tests pass
  • Update documentation if needed
  • Follow the code style guidelines

Release Process

Versioning

UserStore follows semantic versioning (SemVer):

  • MAJOR: Incompatible API changes
  • MINOR: Backwards-compatible functionality additions
  • PATCH: Backwards-compatible bug fixes

Release Checklist

  • Update version in go.mod
  • Update CHANGELOG.md
  • Tag the release (git tag v1.0.0)
  • Push tags (git push origin v1.0.0)
  • Create GitHub release

Documentation

Code Documentation

  • Add comments for exported functions
  • Document complex logic
  • Keep comments up to date

Wiki Documentation

  • Update the LiveWiki documentation for new features
  • Add examples to the getting started guide
  • Update API reference for new methods

Performance Considerations

Database Optimization

  • Use connection pooling
  • Index frequently queried columns
  • Use prepared statements
  • Avoid N+1 query problems

Memory Management

  • Close database connections when done
  • Limit result sets with pagination
  • Reuse objects where possible
