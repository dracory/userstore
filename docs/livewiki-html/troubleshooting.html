Troubleshooting

Common issues and solutions for UserStore

Common Issues

1. Table Already Exists Error

Error: "table already exists" when enabling auto-migration

Cause: The table already exists in the database and auto-migration tries to create it again.

Solution: Disable auto-migration or handle the error gracefully:

// Option 1: Disable auto-migration
userStore, err := userstore.NewStore(userstore.NewStoreOptions{
    DB:                 databaseInstance,
    UserTableName:      "user",
    AutomigrateEnabled: false,
})

// Option 2: Manually run migration and handle error
err = userStore.MigrateUp(context.Background())
if err != nil && !strings.Contains(err.Error(), "already exists") {
    return err
}

2. Database Connection Error

Error: "database is nil" or connection refused

Cause: Database connection is not properly initialized or the database server is not running.

Solution: Ensure the database is running and the connection is properly initialized:

db, err := sql.Open("sqlite", "./userstore.db")
if err != nil {
    log.Fatal(err)
}

// Test the connection
err = db.Ping()
if err != nil {
    log.Fatal(err)
}

userStore, err := userstore.NewStore(userstore.NewStoreOptions{
    DB:                 db,
    UserTableName:      "user",
    AutomigrateEnabled: true,
})

3. Password Comparison Fails

Error: Password comparison always returns false

Cause: Password was not hashed before storage, or comparison is done incorrectly.

Solution: Always use SetPasswordAndHash() for password storage:

// Correct way to set password
err := user.SetPasswordAndHash("securePassword123")
if err != nil {
    return err
}

// Verify password
if user.PasswordCompare("securePassword123") {
    // Password is correct
}

4. User Not Found

Error: UserFindByID returns nil user

Cause: User ID is incorrect, user doesn't exist, or user is soft-deleted.

Solution: Check if the user exists and is not soft-deleted:

user, err := userStore.UserFindByID(context.Background(), userID)
if err != nil {
    return err
}

if user == nil {
    // User not found
    return errors.New("user not found")
}

if user.IsSoftDeleted() {
    // User is soft-deleted
    return errors.New("user has been deleted")
}

5. Query Returns No Results

Error: UserList returns empty slice

Cause: Query filters are too restrictive, or all users are soft-deleted.

Solution: Check query parameters and include soft-deleted if needed:

query := userstore.NewUserQuery().
    SetStatus(userstore.USER_STATUS_ACTIVE).
    SetSoftDeletedIncluded(false)  // Set to true to include soft-deleted

users, err := userStore.UserList(context.Background(), query)
if err != nil {
    return err
}

if len(users) == 0 {
    // No users match the query
}

6. Metadata Not Persisting

Error: Metadata values are not saved or retrieved correctly

Cause: Metadata is not properly set or the user is not updated after setting metadata.

Solution: Ensure you call UserUpdate after setting metadata:

err := user.SetMeta("customField", "customValue")
if err != nil {
    return err
}

// Important: Update the user to persist changes
err = userStore.UserUpdate(context.Background(), user)
if err != nil {
    return err
}

7. Driver Not Detected

Error: SQL generation fails due to unknown driver

Cause: Database driver is not auto-detected correctly.

Solution: Specify the driver name explicitly:

userStore, err := userstore.NewStore(userstore.NewStoreOptions{
    DB:                 databaseInstance,
    UserTableName:      "user",
    DbDriverName:       "mysql",  // or "sqlite", "postgres"
    AutomigrateEnabled: true,
})

8. Connection Pool Exhaustion

Error: "too many open connections" or connection timeout

Cause: Database connections are not being closed properly or connection pool is too small.

Solution: Configure connection pool settings:

db.SetMaxOpenConns(25)
db.SetMaxIdleConns(5)
db.SetConnMaxLifetime(5 * time.Minute)

// Always close connections when done
defer db.Close()

9. Soft Delete Not Working

Error: Soft-deleted users still appear in queries

Cause: Query is not filtering soft-deleted records by default.

Solution: Ensure soft delete filter is applied (default behavior):

query := userstore.NewUserQuery()
// SoftDeletedIncluded defaults to false, so soft-deleted are excluded

users, err := userStore.UserList(context.Background(), query)

10. Update Not Persisting

Error: UserUpdate returns no error but changes are not saved

Cause: User object is not marked as dirty or no fields were changed.

Solution: Ensure fields are actually changed:

// Make sure to actually change values
user.SetEmail("newemail@example.com")

// Update the user
err = userStore.UserUpdate(context.Background(), user)
if err != nil {
    return err
}

Debugging Tips

Enable Debug Mode

userStore.EnableDebug(true)

Check Database State

// Direct database query to check table
rows, err := db.Query("SELECT * FROM user")
if err != nil {
    log.Fatal(err)
}
defer rows.Close()

for rows.Next() {
    // Process rows
}

Log SQL Queries

Enable debug mode to see SQL queries being executed. This can help identify issues with query generation.

When Reporting Issues

  • Include the error message
  • Provide code that reproduces the issue
  • Specify your Go version
  • Specify your database type and version
  • Include relevant configuration

Performance Issues

Slow Queries

  • Add indexes to frequently queried columns
  • Use pagination to limit result sets
  • Use specific column selection instead of SELECT *
  • Optimize connection pool settings

Memory Issues

  • Limit result sets with pagination
  • Close database connections when done
  • Reuse user objects where possible
