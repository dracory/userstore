Project Overview

UserStore is a Go package for user and role management with support for multiple databases (SQLite, MySQL, PostgreSQL). It provides a fluent API, soft delete support, metadata storage, password hashing, and query builder capabilities.

Key Files and Their Purposes

  • interfaces.go - Defines StoreInterface, UserInterface, RoleInterface, and UserQueryInterface
  • store_implementation.go - Implements StoreInterface with database operations
  • store_new.go - Store constructor with NewStoreOptions configuration
  • user_implementation.go - Implements UserInterface with user entity logic
  • role_implementation.go - Implements RoleInterface with role entity logic
  • query_user.go - Implements UserQueryInterface for query building
  • store_user.go - User CRUD operations (Create, Read, Update, Delete, List, Find)
  • sqls.go - SQL generation for table creation and dropping
  • consts.go - Constants for column names, statuses, roles, and error messages
  • id_helpers.go - Short ID generation utilities
  • functions.go - General utility functions

Core Interfaces

StoreInterface

Primary interface for database operations. Key methods:

  • UserCreate, UserUpdate, UserDelete, UserSoftDelete
  • UserFindByID, UserFindByEmail, UserList, UserCount
  • MigrateUp, MigrateDown (database migrations)
  • GetUserTableName, SetUserTableName
  • EnableDebug, GetDB

UserInterface

User entity interface. Key methods:

  • Getters: GetID, GetEmail, GetFirstName, GetLastName, GetStatus, GetRole, etc.
  • Setters: SetID, SetEmail, SetFirstName, SetLastName, SetStatus, SetRole, etc.
  • Status checks: IsActive, IsInactive, IsUnverified, IsSoftDeleted
  • Role checks: IsAdministrator, IsManager, IsSuperuser
  • Password: SetPasswordAndHash, PasswordCompare
  • Metadata: GetMeta, SetMeta, GetMetas, SetMetas, UpsertMetas

UserQueryInterface

Query builder interface. Key methods:

  • Filters: SetID, SetEmail, SetFirstName, SetLastName, SetStatus, SetStatusIn
  • Pattern matching: SetEmailLike, SetFirstNameLike, SetLastNameLike, SetMetaLike
  • Date filters: SetCreatedAtGte, SetCreatedAtLte
  • Pagination: SetLimit, SetOffset
  • Sorting: SetOrderBy, SetSortDirection
  • Options: SetColumns, SetCountOnly, SetSoftDeletedIncluded

Database Schema

User table structure:

  • id (string, 40, primary key) - Auto-generated short ID
  • status (string, 40) - User status
  • first_name, middle_names, last_name (string, 50) - Name fields
  • business_name (string, 100) - Business name
  • phone (string, 20) - Phone number
  • email (string, 100) - Email address
  • password (string, 255) - Bcrypt hashed password
  • role (string, 50) - User role
  • country (string, 2) - Country code
  • timezone (string, 40) - Timezone
  • profile_image_url (string, 255) - Profile image URL
  • metas (text) - JSON-encoded metadata
  • memo (text) - Free-form memo
  • created_at, updated_at, soft_deleted_at (datetime) - Timestamps

Key Design Patterns

  • Interface-based design - All major components use interfaces for testability
  • Method chaining - Setters return interface for fluent API
  • Builder pattern - Query builder for complex queries
  • Soft delete - Uses soft_deleted_at column instead of hard delete
  • Metadata storage - JSON in metas column for flexible custom fields
  • Password hashing - Bcrypt hashing for security

Common Usage Patterns

Store Initialization

userStore, err := userstore.NewStore(userstore.NewStoreOptions{
    DB:                 databaseInstance,
    UserTableName:      "user",
    AutomigrateEnabled: true,
    DebugEnabled:       false,
})

User Creation

user := userstore.NewUser().
    SetStatus(userstore.USER_STATUS_ACTIVE).
    SetFirstName("John").
    SetLastName("Doe").
    SetEmail("test@test.com")

err := user.SetPasswordAndHash("password123")
err = userStore.UserCreate(context.Background(), user)

User Query

query := userstore.NewUserQuery().
    SetStatus(userstore.USER_STATUS_ACTIVE).
    SetLimit(10).
    SetOrderBy("created_at").
    SetSortDirection("DESC")

users, err := userStore.UserList(context.Background(), query)

API Convention

  • Getters use "Get" prefix: GetID(), GetName(), GetEmail()
  • Setters use "Set" prefix: SetID(), SetName(), SetEmail()
  • Boolean checks use "Is" prefix: IsActive(), IsAdministrator()

Important Notes

  • Uses soft delete by default (soft_deleted_at column)
  • Passwords must be hashed using SetPasswordAndHash()
  • Metadata is stored as JSON in the metas column
  • Supports SQLite, MySQL, PostgreSQL via SQL builder
  • Auto-migration can be enabled via AutomigrateEnabled option
  • Debug mode can be enabled via EnableDebug() method
